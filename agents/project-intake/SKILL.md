# Project Intake

Use at the start of a substantial new task or when project context is unclear.

1. Identify project type and domain without assuming one.
2. Read repository-level instructions and relevant documentation.
3. Identify stack, runtime, platforms, dependencies, architecture, and current state.
4. Restate the user's goal and constraints.
5. Determine whether this is new work, a bug fix, a refactor, migration, review, or research.
6. Define acceptance criteria and a verification plan.
7. Ask only for information that materially blocks safe progress; otherwise state assumptions.

Output a concise project brief for the Owner.
