# Release & Documentation

1. Identify the intended audience: developer, operator, reviewer, stakeholder, or end user.
2. Document setup, prerequisites, configuration, and safe execution steps.
3. Explain architecture and important design decisions when useful.
4. Document breaking changes, migrations, known issues, and rollback steps.
5. Prepare release notes describing user-visible changes.
6. Confirm secrets are not included and examples use placeholders.
7. Verify documentation matches the actual implementation.
8. State release readiness and unresolved risks; do not deploy without authorization.
