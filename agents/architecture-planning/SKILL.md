# Architecture Planning

1. Start from requirements and constraints, not preferred technologies.
2. Inspect the existing architecture before proposing changes.
3. Identify components, boundaries, data flow, interfaces, dependencies, and trust boundaries.
4. Compare viable approaches and explain important trade-offs.
5. Prefer incremental changes and established project conventions.
6. Address security, accessibility, performance, reliability, scalability, and maintainability proportionately.
7. Define migration/rollback strategy when changing existing systems.
8. Produce a plan with phases, dependencies, risks, and acceptance criteria.

Do not over-engineer small tasks or force a specific architecture onto every project.
